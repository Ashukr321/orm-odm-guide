01 — Concept

Database vs DBMS

A database is an organized collection of data. A DBMS is the software that stores, finds, updates and protects it, even with many users at once.

03 — Vocabulary

Core Terms

  • Schema: the structure (tables, fields, types)
  • Record: one row or document
  • Query: a request to read or change data
  • CRUD: Create, Read, Update, Delete
  • Index: a lookup structure for fast search
  • Transaction: changes that succeed or fail together
  • Constraint: a rule the DB enforces

05 — Internals

How a Database Works Inside

Parser
→
Query planner
→
Executor
→
Buffer cache (RAM)
→
WAL + data pages (disk)
  • Pages: data is read in fixed blocks (8 KB PostgreSQL, 16 KB InnoDB).
  • Buffer cache: hot pages stay in RAM, which is far faster than disk.
  • Write-ahead log: each change is logged first and replayed after a crash, so committed data is never lost.
  • Planner: you say what you want, the DB decides how. EXPLAIN shows the plan.

  • The database runs as its own server, reached over TCP: 5432 PostgreSQL · 3306 MySQL · 27017 MongoDB · 6379 Redis.
  • The API uses a connection pool and runs related queries in a transaction.
  • SQLite is the exception: a library that reads a local file directly.
06 — Workloads

OLTP vs OLAP

Query"Get order #123""Revenue by city, 3 years"
Rows / queryA fewMillions

Heavy analytics on the production database slows the app down. At scale, copy the data to an OLAP store.

07 — Operations

Properties That Matter in Production

ACID — Atomic, Consistent, Isolated, Durable transactions.
Replication — copies on other servers for availability and spreading reads.
Backups — snapshots plus the log for point-in-time restore. An untested backup is not a backup.
Security — roles, TLS, encryption at rest, parameterized queries against SQL injection.

Managed (RDS, Neon, Supabase, Atlas) handles upgrades, backups and failover. Self-hosted is cheaper, but that work is yours.

Interview-Ready Summary

What to Say Cold

  • A database is organized data. A DBMS is the software that stores, queries and protects it.
  • Compared with files, it adds concurrency, durability, indexes, constraints, transactions, access control.
  • Every app is built on CRUD.
  • Types: relational, document, key-value, wide-column, graph, plus search, time-series and vector.
  • Inside: parser → planner → executor, with a buffer cache and a write-ahead log.
  • OLTP runs the app, OLAP analyzes it. Keep them separate at scale.
