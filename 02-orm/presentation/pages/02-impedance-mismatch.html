What "Impedance Mismatch" Means

Your code models data as a graph of objects: nested, referencing each other, with inheritance and methods.

A relational database models data as flat tables of rows, linked by foreign keys and combined with set-based JOINs.

The object-relational impedance mismatch is the set of problems you hit when moving data between these two models.

Without an ORM, you write that translation code yourself, by hand, for every query.

Granularity & Inheritance

Granularity: one object, many columns

jsclass User { address = { street: 'MG Road', city: 'Patna' } }   // nested object
-- users(id, address_street, address_city)                       -- flat columns

Inheritance: tables can't extend tables

jsclass User  { id; email }
class Admin extends User { permissions }
-- Option A: single table  users(id, email, type, permissions NULL)
-- Option B: table per class  users(id, email) + admins(user_id, permissions)

ORMs let you pick a strategy (Hibernate: SINGLE_TABLE, JOINED; TypeORM: @TableInheritance).

Identity & Navigation

Identity: two loads, two objects?

jsconst a = await repo.findOne({ where: { id: 1 } });
const b = await repo.findOne({ where: { id: 1 } });
a === b   // false without an identity map, even though it's the same row

Navigation: the road to N+1

jsfor (const user of users) {
  const posts = await user.getPosts();   // 1 query per user → N+1 queries
}

Objects walk a graph one hop at a time. Databases want one set-based query. Eager loading (include) bridges it.
