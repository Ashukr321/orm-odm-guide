The Pipeline

1. Define models   →  model User { id Int @id … }           schema / classes
2. Call the API    →  prisma.user.findMany({ … })
3. Build SQL       →  SELECT … FROM "users" WHERE … LIMIT $1
4. Run via driver  →  pooled connection, parameters sent separately
5. Hydrate         →  rows → typed objects, relations attached
6. Track changes   →  (some ORMs) diff objects, flush UPDATEs in one transaction

Steps 1–5 happen in every ORM. Step 6 (change tracking) only exists in Unit of Work ORMs like MikroORM, Hibernate and EF Core.

Define Models

prismamodel User {
  id        Int      @id @default(autoincrement())
  email     String   @unique
  name      String
  createdAt DateTime @default(now()) @map("created_at")
  posts     Post[]
  @@map("users")
}

model Post {
  id        Int     @id @default(autoincrement())
  title     String
  published Boolean @default(false)
  author    User    @relation(fields: [authorId], references: [id])
  authorId  Int     @map("author_id")
  @@map("posts")
}

The model is the single source of truth for types, relations and migrations.

API Call → SQL → Driver

jsawait prisma.user.findMany({
  where: { email: { endsWith: '@example.com' } },
  orderBy: { createdAt: 'desc' },
  take: 10,
});
sqlSELECT "id", "email", "name", "created_at"
FROM "users"
WHERE "email" LIKE $1          -- $1 = '%@example.com'
ORDER BY "created_at" DESC
LIMIT $2                       -- $2 = 10

Values travel as parameters, separate from the SQL text. Turn on query logging (new PrismaClient({ log: ['query'] })) to see this yourself.

Hydration: Rows → Objects

row:     { id: 1, email: 'ashu@example.com', created_at: 2026-09-25 10:00:00+00 }
object:  { id: 1, email: 'ashu@example.com', createdAt: Date(2026-09-25T10:00:00Z),
           posts: [ { id: 7, title: 'Hello ORM', published: true } ] }
  • Columns are renamed (created_at → createdAt).
  • Types are converted (TIMESTAMPTZ → Date, BIGINT → bigint).
  • Related rows are attached as nested objects.
  • TypeScript knows the exact shape of the result, including posts.

Writes, Change Tracking & Transactions

js// Unit of Work (MikroORM): change objects, then flush once
const user = await em.findOneOrFail(User, 1);
user.name = 'Ashutosh';
em.persist(new Post({ title: 'New', author: user }));
await em.flush();        // → BEGIN; UPDATE users…; INSERT INTO posts…; COMMIT;

// Prisma: explicit calls, grouped in a transaction
await prisma.$transaction([
  prisma.user.update({ where: { id: 1 }, data: { name: 'Ashutosh' } }),
  prisma.post.create({ data: { title: 'New', authorId: 1 } }),
]);

Migrations

Most ORMs compare your models with the database and generate the SQL to bring them in sync.

npx prisma migrate dev --name add_user_phone
# → prisma/migrations/20260925_add_user_phone/migration.sql
#   ALTER TABLE "users" ADD COLUMN "phone" TEXT;

Migrations are versioned files in git, so every environment (dev, CI, production) gets the same schema, in the same order.
